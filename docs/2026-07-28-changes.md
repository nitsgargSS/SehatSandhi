# What changed on 28 July 2026 — and how to check it

37 commits, 17 database migrations, both projects. This is a testing checklist,
not a changelog: each section says what to do and what should happen.

**Where to test.** Sandbox — https://sehat-sandhi-staging.vercel.app/?env=sandbox
(the `?env=sandbox` matters; without it you are on production data). The admin
panel is at `/ng-ctrl-2026`, the clinic dashboard at `/doctor/login`.

**Anything marked ⚠ is a known gap, not a bug to report.**

---

## 1. Pricing — one editable number

**What was wrong.** The price was written into the plan's *name*
(`Launch offer — ₹1,000/month`) and into its permanent *code* (`launch_1000`).
Changing the price in admin left the headline promising the old one. A seat cap
also advanced the queue by itself, so the 51st business would have been quoted
₹2,000 with nobody deciding that.

**Check:**
1. Admin → Billing → **Price on the live plan**. Type `2500`, Save.
2. Open `/business` in another tab — the price card should read ₹2,500.
3. Start a signup: the quote should be ₹2,500 + GST.
4. Set it back to `1000`.

Prices can no longer be typed into a plan name or code — both are rejected.
Nothing changes the price now except someone typing one; all seat caps are
cleared.

## 2. Term is the buyer's choice

Checkout used to preselect a 5-month term and the landing page advertised the
5-month total as if it were the offer.

**Check:** signup step 4 opens at **1 month**. Picking 1 / 3 / 5 changes the
total, and GST is added on top and shown separately.

## 3. GST

Live on both projects: **NG Technologies, 06AELPG4279G1ZD**, Haryana, 18%,
SAC 998365.

**Check:**
1. Signup step 4 shows a **"Your GST number"** field (optional).
2. Type a wrong GSTIN — it is refused, and payment is blocked until corrected.
   The number you first gave (`01…`) fails its own check digit; `06…` is right.
3. Type a valid one — it names the state and says whether the invoice will show
   CGST+SGST or IGST.
4. A clinic can also add its GSTIN later from **Clinic → GST number**.

Invoices are gapless per financial year (`SS/2026-27/0001`…), and the CGST/SGST
vs IGST split follows the buyer's state.

## 6. Reports

Two audiences, both new.

**Clinic → Reports:** appeared in search → profile opened → WhatsApp tapped →
booked, plus daily trends and appointment outcomes. 7 / 30 / 90 days.

**Admin → Reports:** visitors, searches, signups, bookings, and **"What patients

could not answer, which is the argument for entering a town.

⚠ **Production has almost no data.** Event recording started today against a site

## 7. Practice locations and hourly windows

A doctor can sit in more than one place, and patients book an **hourly window**
rather than a 15-minute slot.

**Check — Clinic dashboard → Schedule:**
1. Add a second location (name, address, PIN, desk phone). No extra charge.
2. Set hours per location, with **patients per window** — your number, per
   clinic.
3. The patient-facing profile lists every clinic.

Capacity is enforced: a full hour is refused by name and time, cancelling frees
the seat, and a doctor cannot be booked at two locations in the same hour.

⚠ **The WhatsApp bot is a separate backend and has not been updated.** Bookings
still work and default to the primary location, but until the bot asks "which
clinic?" patients cannot choose one or see hourly windows.

## 8. Hospitals

**What was wrong.** A hospital registered as one anonymous listing. Its doctors
were invisible and it paid a single GP's price.

**Check:**
1. Signup → **Hospital** → step 2 now has **"Your doctors"**. Add three.
2. The price follows: **₹1,000 per doctor**, so 3 doctors = ₹3,000 + GST =
   ₹3,540. It should move as you add and remove.
3. Each consultant becomes a real listing — own profile, own calendar, findable
   by speciality.
4. Clinic dashboard → **Your doctors** to add or remove later. The cost of a
   change is shown before you confirm it.

The model is a dropdown in **Admin → Billing → "Hospitals with several doctors"**
— per doctor, include-some-then-charge, or ignore headcount. All screens follow
whichever you pick.

## 9. Doctor speciality — was being thrown away

**What was wrong.** "Category / speciality" was free text that was never saved.
Every doctor was stored as `GEN`, so a cardiologist would never have appeared in
a cardiology search, and nobody would have noticed.

**Check:**
1. Signup step 2 → **Speciality** is now a dropdown and is required.
2. Register as a cardiologist, approve it, then search Cardiology in that area —
   they should appear.
3. Admin → Doctors → the Speciality column is editable. Changing it to a
   *business* type (Pharmacy, Lab…) asks for confirmation, because that changes
   how they are billed.

## 11. Clinic login — by WhatsApp number

**What was wrong.** A business could sign up through the wizard, pay, be
activated, and **have no way into its dashboard.** The wizard never created an
account and the login form asked for an email and password that did not exist.

**Check at `/doctor/login`:**
1. Enter a registered number → a 6-digit code.
   ⚠ **Sandbox shows the code on screen** — no SMS provider is wired yet.
2. Wrong code is refused; five wrong tries burns it; resend waits 60 seconds.
3. An unregistered number gets the *same* message, so the form cannot be used to
   discover which numbers are businesses.
4. Correct code → the dashboard.

One login reaches every listing on that number — a clinic and a pharmacy on the
same phone both appear. The old email/password form is still there behind a link
for anyone who registered that way.

## 12. Clinic dashboard

| Tab | What it shows |
|---|---|
| Today | today's windows and recent bookings |
| Appointments | **all** of them — date range, status filter, patient search |
| Schedule | locations, hours, capacity |
| Clinic | staff, camps, GSTIN, hospital roster |
| Bills | every invoice, with the CGST/SGST split spelled out |

**What was wrong.** It loaded 20 appointments and no more, and the "This month"
figure was counted from those 20 — so it silently under-reported past the

**Different verticals see different tabs.** A pharmacy or insurance agent has no
appointment book, so they get Hours & branches, Business, Bills and Reports.

## 13. Pharmacy, insurance, ambulance — no monthly fee

As decided today, the flat plan applies to **doctors, hospital and lab only**.
The other three are free to list and owe 10% of billing, which is what their
pages have always said.

**Check:** signup as a Pharmacy — the wizard should show **no monthly fee**, the
10% terms, and **no Pay button**. Attempting to pay is refused server-side and
creates no payment row.

⚠ **The 10% is a term, not something we can bill yet.** We can see a WhatsApp
tap but not what a pharmacy dispensed. Until they report their billing, these
are free listings.

⚠ Their signup takes no payment, so the listing stays **pending** until you
approve it in admin — the intended gate for drug licence and IRDA checks.

## 14. Payments

**Razorpay is working.** A real test payment went through end to end:
`pay_TIu7camfOmiFuT`, ₹3,540, listing activated, price and term locked, invoice
`SS/2026-27/0005` issued and reconciling exactly.

**A webhook now exists** so a dropped browser cannot lose a payment. Previously
the whole chain depended on the customer's browser returning from Checkout; if
their phone died, Razorpay had the money and we had no record. Registered on the
test account for `payment.captured`, verified against forged, genuine and
duplicate deliveries — a retry returns the *same* invoice number, never a second.

**Test cards:** `5267 3181 8797 5449` or `4386 2894 0766 0153`, any future
expiry, any CVV. On the OTP page **any 4–10 digits** works. Avoid
`4111 1111 1111 1111` — Indian gateways treat it as international.

⚠ **Still untested: closing the tab mid-payment.** A normal payment fires both
paths, which does not exercise the webhook's reason for existing. Pay, then kill
the tab while Razorpay's spinner is up — the listing should still activate and
the invoice still issue.

⚠ **Production has no Razorpay keys and no webhook.** Live keys need their own
webhook pointing at the production project.

## 15. Site speed

Every page used to ship in one 865 kB bundle, so a patient opening the homepage
from a WhatsApp link downloaded the admin dashboard and the billing screens
before seeing anything. Now **496 kB** initial load (151 kB gzipped, from 215 kB)
— 43% less, which matters on a rural connection.
